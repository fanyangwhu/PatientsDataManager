# 患者临床信息管理系统

一个完全本地运行的临床数据收集网站。字段由你自己定义，支持增删改查、按字段筛选与排序、
Excel 导入导出，多人共用时带账号权限与操作审计。

- **技术栈**：Python + Flask + SQLite，零外部服务、零云依赖，断网可用
- **部署形态**：一台电脑当服务器，科室其他电脑用浏览器访问（不用装任何东西）
- **数据位置**：全部在你自己的硬盘上，`data/registry.db` 一个文件

## 一、快速开始（Windows）

> 只有**当服务器的那台电脑**需要安装 Python，科室其他电脑什么都不用装，
> 直接用浏览器访问地址即可。

1. 安装 **Python 3.9 以上**（[python.org 下载](https://www.python.org/downloads/)），
   安装时**务必勾选 `Add Python to PATH`**（安装界面最下方那个小方框）。
2. 双击 `install.bat` —— 只需运行一次，自动装好依赖。
   看到 `Setup completed successfully!` 就成功了。
3. 双击 `start.bat` 启动。窗口里会显示两个地址：
   - 本机：`http://127.0.0.1:5000`
   - 局域网：`http://192.168.x.x:5000` ← 科室其他电脑用这个
4. 用默认管理员登录：**admin / admin123**，首次登录会强制你改密码。

> 首次启动时 Windows 防火墙可能弹窗，选「允许访问」（专用网络）。
>
> **窗口不要关**：黑窗口是服务器，关掉系统就停了。可以最小化。

### 三个脚本分别做什么

| 脚本 | 什么时候用 | 作用 |
|---|---|---|
| `install.bat` | 只用一次 | 建虚拟环境、装依赖 |
| `start.bat` | 每天开机后 | 启动系统（依赖没装会自动补装） |
| `check.bat` | 出问题时 | 只读体检：把环境信息打印出来，方便排查 |

`start.bat` 也支持指定端口：`start.bat 8080`。

> **脚本输出为什么是英文？**
> 中文的 `.bat` 在部分 Windows 上会被命令行按 GBK 误读，中文提示会变成乱码并被当成命令执行，
> 报「'xxx' 不是内部或外部命令」。所以三个脚本全部写成纯英文，彻底避开这个问题。
> 网页界面仍然是全中文，不受影响。

Mac / Linux：
```bash
pip install -r requirements.txt
python run.py            # 局域网可访问
python run.py --local-only   # 只允许本机
```

## 二、上手四步

| 步骤 | 位置 | 说明 |
|---|---|---|
| 1. 配字段 | 字段管理 | 先想清楚要收集哪些项目，再建字段 |
| 2. 录数据 | 患者列表 → 新建 | 或走 Excel 批量导入 |
| 3. 查数据 | 患者列表 | 关键词搜索 + 每列筛选 + 点表头排序 |
| 4. 出数据 | 导出 | 按当前筛选结果导出 Excel / CSV |

### 字段类型
单行文本、多行文本、数字、日期、单选、多选（用分号分隔）、是/否。

### 字段属性
- **必填**：录入和导入时强制校验
- **值唯一**：如住院号、身份证号，重复会报错；也是「更新已有记录」导入的匹配依据
- **列表显示 / 参与搜索**：控制列表页列与关键词搜索范围
- **敏感脱敏**：如姓名、电话，在列表中显示为 `张*`、`138****001`，管理员在详情页可见完整值
- **主标识**：设一个字段（如姓名）作为列表首列
- **停用**：不想再用但保留历史数据，就停用，不要删除

## 三、Excel 导入

1. 先在「患者列表 → 下载导入模板」拿模板（含一行示例和一个「填写说明」页）。
2. 按模板填数据，**不要改第一行的字段名**。
   - 日期写 `2025-03-01`（也认 `2025/3/1`、`2025年3月1日`）
   - 是/否 填「是」「否」
   - 多选填 `高血压;糖尿病`（分号分隔）
3. 上传后系统会**先预览再写入**：
   - 自动按字段名匹配列，匹配错了可以在下拉框里手动改
   - 逐行校验：必填为空、数字/日期格式错、选项不存在、唯一值重复，都会标出**具体行号和原因**
   - 两种导入模式：
     - **全部新增**（默认）
     - **按唯一字段更新**：按住院号等字段匹配，已存在就覆盖更新，不存在就新增 —— 反复导同一份表不会重复

> 导入前务必先备份。导入的记录会记录创建人，导出时带「创建人/创建时间」列。

## 四、多人共用与权限

| 角色 | 权限 |
|---|---|
| 管理员 | 全部：字段管理、用户管理、审计日志、数据增删改、备份 |
| 录入员 | 录入、修改、删除、导入导出（不能改字段和用户） |
| 查看者 | 只读、可导出 |

**审计日志**记录每一次登录、新增、修改、删除、导入、导出（含操作人、时间、IP、变更前后内容）。
删除的记录会在日志里保存完整快照，误删后可查回内容。

⚠️ **重要**：不要让多台电脑同时启动程序指向同一个数据库文件。
正确做法是「一台机器跑服务，其他人浏览器访问」。

## 五、备份与迁移

- 一键备份：数据总览 →「备份数据库」，或管理员在审计日志页导出
- 手动备份：直接复制 `data/registry.db`（先停程序再复制最稳妥）
- 迁移到新电脑：整个文件夹拷过去，或只拷 `data/registry.db` 放到新装的 `data/` 目录里
- 换端口：`python run.py --port 8080`
- 把数据库放到其他盘：设置环境变量 `REGISTRY_DATA_DIR=D:\临床数据`

## 六、常见问题

**Q：双击 .bat 报「'xxx' 不是内部或外部命令」或一堆乱码中文？**
这是批处理文件的编码问题。请确认你用的是本压缩包里的 `install.bat` / `start.bat`
（新版脚本已改为纯英文，不会再出现该问题）。如果还报错，多半是 Python 没装好，
直接到 [python.org](https://www.python.org/downloads/) 重装并勾选 `Add Python to PATH`。

**Q：提示 "Python 3.9 or newer was not found"，但我明明装了 Python？**
安装时漏勾了 `Add Python to PATH`。解决：重新运行 Python 安装包 → 选 `Modify` →
`Add Python to environment variables`，或者直接双击 `start.bat`（它会自动尝试 `py -3`）。

**Q：双击 start.bat 窗口一闪而过？**
用命令行进入目录执行 `python run.py` 能看到报错。多半是 Python 没装或没勾 Add to PATH。

**Q：提示端口被占用？**
换端口：`python run.py --port 8080`。

**Q：同事打不开我给的网址？**
① 确认两人同一局域网；② 关闭服务器电脑的防火墙或允许 Python 通过；③ 用 `ipconfig` 查到的 IPv4 地址。

**Q：忘了管理员密码？**
在程序目录执行 `python -m flask --app run:create_app reset-password`，按提示输入用户名和新密码。
（Linux/Mac 用 `flask --app run:create_app reset-password`）

**Q：导出的 Excel 打开是乱码？**
一般不会出现（UTF-8）。若用 WPS/老版 Excel 打开 CSV 乱码，请用「导出 Excel」而不是 CSV。

## 七、目录结构

```
patient-registry/
├── run.py              启动入口
├── requirements.txt    依赖
├── install.bat         首次安装依赖（Windows）
├── start.bat           启动（Windows）
├── app/
│   ├── __init__.py     应用工厂、仪表板、备份
│   ├── models.py       数据模型（字段定义 / 患者 / 字段值 / 日志）
│   ├── fields.py       字段管理
│   ├── records.py      患者增删改查、Excel 导入导出
│   ├── auth.py         登录、权限、改密码
│   ├── admin.py        用户管理、审计日志
│   ├── utils.py        查询构建、Excel 读写、校验
│   ├── templates/      页面模板
│   └── static/         样式与脚本
└── data/
    ├── registry.db     数据库（唯一的数据文件）
    └── backups/        备份
```

## 八、隐私与安全提示

- 系统只做**内网访问控制**，没有 HTTPS 和防黑客能力，请勿直接暴露到公网。
- 患者数据属敏感信息，建议：数据库文件放在加密盘、定期备份、离职人员及时停用账号。
- 如需更高安全等级（强制复杂密码、登录失败锁定、操作留痕导出归档），可在现有代码上继续加固。
